# Ruby Standards

Covers the conventions a Ruby codebase must hold uniform: RuboCop configuration and the disable policy, naming and method-signature shape, object construction (modules, value objects, blocks, nil), error and dependency discipline, and the test and performance habits that keep a large codebase honest. Ruby's dynamism means most of these conventions are not enforced by the language at all — a divergent `attr_accessor`, a `rescue Exception`, or a monkey-patched `String` will pass review and tests, then break production in a file nobody re-read. The audit's job is to find where the repo drifted from its own canonical form.

## When This Applies

- The repository contains `.rb`, `.rake`, `.gemspec`, `Rakefile`, `Gemfile`, `Gemfile.lock`, or `config.ru`.
- RuboCop is absent, or `.rubocop.yml` exists but `.rubocop_todo.yml` is hand-edited, stale, or missing.
- The tree mixes `# frozen_string_literal: true` and files without it, or a file sets it to `false`.
- Both `attr_reader` and `attr_accessor` are used for the same kind of state, or `Struct`, `Data.define`, and `OpenStruct` all appear.
- A file reopens `String`, `Integer`, `Array`, `Hash`, `Object`, or a gem class instead of using `refine`.
- Ruby code is present with RSpec specs, Minitest specs, or both, and the spec directory has no convention for `let` versus `before`.
- A Rails app shows repeated single-row queries inside a loop over an association.
- Sibling modules govern the surrounding tree: [std-yaml-json.md](std-yaml-json.md) for the YAML config itself, [std-docs.md](std-docs.md) for README and docstring standards, [std-git.md](std-git.md) for the `.gitignore` entry that must exclude `.rubocop_cache` and `vendor/bundle`.

## Lint, Format, and the Disable Policy

RuboCop is the enforcement layer; the [community Ruby style guide](https://rubystyle.guide/) is the baseline it encodes. Configuration is committed, not per-developer.

```ruby
# .rubocop.yml
inherit_from: .rubocop_todo.yml
inherit_mode:
  merge: [Exclude]

plugins:
  - rubocop-performance
  - rubocop-rspec

AllCops:
  TargetRubyVersion: 3.4
  NewCops: enable
  Exclude: ["db/schema.rb", "vendor/bundle/**/*", "tmp/**/*"]
Layout/LineLength:
  Max: 120
Metrics/MethodLength:
  Max: 15
Metrics/ParameterLists:
  Max: 6
  CountKeywordArgs: true
Style/ClassAndModuleChildren:
  EnforcedStyle: compact
```

Since RuboCop 1.72, extensions load through the `plugins:` key; the older `require:` key still loads them but is deprecated for that purpose. `TargetRubyVersion` must match the `ruby` directive in the Gemfile and the CI image — a mismatch makes cops silently skip syntax they cannot parse. `NewCops: enable` means new RuboCop releases turn on new cops as they are added, so a version bump is a code change with a review, not a background surprise.

The disable policy is the part that decays first. A workable one:

- **Bulk debt goes to `.rubocop_todo.yml`, generated by `rubocop --auto-gen-config`.** Never hand-edit it into shape; regenerate it as offenses are paid down so the file shrinks. `--no-offense-counts`, `--no-auto-gen-timestamp`, and `--auto-gen-only-exclude` keep it diff-stable, and `--exclude-limit` bounds how many paths a cop gets before it is excluded wholesale.
- **Inline disables carry a reason and a bounded scope.** `# rubocop:disable Metrics/MethodLength -- generated table builder` on the `def` line, re-enabled on the `end`. A disable with no reason is a defect; `# rubocop:disable all` is banned.
- **`# rubocop:todo` is temporary debt** and must name an issue in the same line's reason, because it will be swept into the next `.rubocop_todo.yml` regeneration.
- **`Lint/RedundantCopDisableDirective` fails the build** when a disable stops being needed, so disables cannot outlive their cause.
- **Department-level opt-outs live in `.rubocop.yml`**, reviewed like code, with the reason recorded in the repo's standards doc rather than a per-file comment.

Run safe corrections with `rubocop --autocorrect` (`-a`) and unsafe ones with `rubocop --autocorrect-all` (`-A`); the second includes cops whose fix can change behavior. In CI, run `rubocop --force-exclusion --display-cop-names` with no `--ignore-disable-comments`, so the disable policy above is actually binding. Cache the `.rubocop_cache` directory between CI runs and gitignore it.

## Naming, Signatures, and Value Objects

### Naming is enforced, not preferred

| Element               | Convention                            | Cop                                                            |
| --------------------- | ------------------------------------- | -------------------------------------------------------------- |
| Methods, variables    | `snake_case`                          | `Naming/MethodName`, `Naming/VariableName`                     |
| Classes, modules      | `CamelCase`                           | `Naming/ClassAndModuleCamelCase`                               |
| Constants             | `SCREAMING_SNAKE_CASE`                | `Naming/ConstantName`                                          |
| Predicates            | end in `?`, return a boolean          | `Naming/PredicateName` — `ForbiddenPrefixes` defaults to `is_` |
| Dangerous variants    | end in `!` only for the mutating twin | no cop — enforced in review, not by lint                       |
| Short parameter names | below `MinNameLength` (default 3)     | `Naming/MethodParameterName`                                   |
| Memoized ivars        | ivar name matches the method name     | `Naming/MemoizedInstanceVariableName`                          |
| Block forwarding      | `def m(...)`, pass `(...)`            | `Naming/BlockForwarding`                                       |

Cop names move between RuboCop releases — the Naming department has been reorganized more than once. Resolve the current name against the pinned version with `rubocop --show-cops Naming` instead of trusting documentation written for another release.

`?` means "answers a question", so `user.active?` is right and a `user.active?` that memoizes or writes is wrong. `!` is not emphasis: it marks the destructive sibling of a pure method (`sort`/`sort!`, `save`/`save!`), or a method that raises where the non-`!` form returns a sentinel. A `!` method with no non-`!` counterpart, or a `!` method that does not mutate its receiver, is a naming lie that costs every future reader. `Naming/PredicateName`'s default `ForbiddenPrefixes` rejects `is_`/`has_` prefixes, which is what the community guide asks for; renaming a public method is an API change, so pair it with a deprecation alias rather than a silent rename.

### Keyword arguments, not option hashes

A trailing `options = {}` is an unchecked dictionary: typos become silent no-ops and the signature documents nothing.

```ruby
def render_report(account, period:, format: :pdf, include_charts: true)
  # period and format are required/known; the call site is self-describing
end

render_report(account, period: period, format: :csv)
```

```python
def render_report(account, *, period, format="pdf", include_charts=True):
    ...
```

Ruby 3.0 separated keyword arguments from positional arguments, so a method declaring keywords no longer accepts a bare Hash: `render_report(account, {period: p})` raises `ArgumentError` instead of silently working. Required keywords raise `ArgumentError: missing keyword: :period` at the call site, which is exactly the validation a positional option hash never gave you. Ruby 3.4 also added `it` as an implicit first block parameter (`items.map { it.name }`), which removes the `_1` noise; a local variable named `it` in the same scope warns.

### Value objects: `Data.define` first, `Struct` second

```ruby
Point = Data.define(:x, :y)

p1 = Point.new(1, 2)
p1.with(y: 9)                # => #<data Point x=1, y=9>
p1.to_h                      # => {x: 1, y: 2}
p1 in [0, y]                 # pattern matching: positional and keyword both work
```

`Data.define` (Ruby 3.2+) produces an immutable, value-equal object with `==`, `eql?`, `hash`, `to_h`, `with`, `deconstruct`, and `deconstruct_keys` — usable as a Hash key, safe to share across threads, and pattern-matchable. `Struct.new(:x, :y, keyword_init: true)` is the older option: instances are mutable, `Struct#==` also returns true when compared against a plain Array with equal members, and mutability makes a Struct a bad Hash key. Use Struct only when a mutable record is genuinely required.

`OpenStruct` is neither: it is `method_missing`-based (so a typo returns `nil` instead of raising), it is measurably slower than both alternatives, and it is scheduled to leave the default gems in Ruby 3.5 — Ruby 3.4 already warns when it is loaded. Replace it with `Data.define`, `Struct`, or a plain `Hash` with `fetch`.

| Concern           | `Data.define`     | `Struct`                    | `OpenStruct`             |
| ----------------- | ----------------- | --------------------------- | ------------------------ |
| Mutability        | Frozen            | Mutable                     | Mutable                  |
| Equality          | Members and class | Members and class, or Array | Object identity          |
| Unknown attribute | `NoMethodError`   | `NoMethodError`             | Returns `nil`            |
| Hash key safe     | Yes               | No (mutable)                | No                       |
| Stdlib status     | Core since 3.2    | Core                        | Leaving default gems 3.5 |

## Objects: Modules, Composition, and Nil

### Modules namespace and mix in; they do not accumulate state

`include` adds instance methods, `extend` adds singleton (class-level) methods, and `prepend` inserts the module _ahead of_ the class in the ancestor chain so the module's method can call `super` and reach the class's own implementation — the correct tool for decorators and instrumentation, where `alias_method` chains are not.

Ancestor order is the part that surprises people. With `class C; include A; include B; end`, `C.ancestors` is `[C, B, A, Object, ...]`: the **last** included module is closest to the class and wins. Prepended modules come before the class in reverse order of `prepend`.

`module_function` turns the methods that follow it into private instance methods _and_ public module methods, which is the stdlib idiom for a namespace of stateless helpers; `extend self` does the same thing less explicitly. A module with instance variables, or one that needs `initialize`, is a class wearing the wrong keyword. Prefer composition to mixin: a module that requires the host class to have specific ivars or to define a callback is implicit coupling no signature expresses, whereas a constructor argument makes the dependency visible and testable.

```ruby
class InvoicePrinter
  def initialize(renderer:, clock: Time)
    @renderer = renderer
    @clock = clock
  end
end
```

`require "forwardable"` and `def_delegators :@renderer, :to_html` give delegation without inheritance; `SimpleDelegator` (stdlib) covers the dynamic case. Reserve `ActiveSupport::Concern` for Rails codebases that already use it — its `included do ... end` and `class_methods do ... end` blocks are real conveniences, but a concern with more than a handful of methods is a class that has not been extracted.

### `attr_reader` is the default; writers are a design decision

`attr_accessor` publishes a setter for every attribute, so any caller can put an object into a state no invariant allows. Default to `attr_reader`, add a private `attr_writer` when only internal code assigns, and write an explicit public method when assignment must validate or notify. `Style/TrivialAccessors` catches accessors that should have been `attr_reader` in the first place.

### Nil: normalize at the boundary, then stop checking

```ruby
Config = Data.define(:name, :timeout, :tags)

def build_config(payload)
  Config.new(name: payload.fetch("name"),
             timeout: payload.fetch("timeout", 30),
             tags: Array(payload["tags"]))
end

config.name&.upcase
```

Two rules carry most of the weight. First, convert external input (JSON, env, params) into symbols and concrete types at exactly one boundary, then the rest of the code can assume them: `JSON.parse(body, symbolize_names: true)` avoids the string-key/symbol-key split that otherwise reappears in every caller. `HashWithIndifferentAccess` in Rails is the same idea applied at the parameter boundary. Second, use `&.` for genuinely optional chains — it short-circuits the _entire_ remaining chain, so `order&.customer&.email` is fine but `order&.customer.email` hides a second nil. Do not paper over an invariant with `&.`; if `order.customer` is always present, let it raise.

`Hash#fetch` is the boundary primitive: it raises `KeyError` for a missing key and accepts a block, whereas `fetch(:k, expensive_default)` evaluates the default eagerly even when the key exists. `nil.to_a`, `nil.to_h`, and `nil.to_s` all return empty values, so a nil that reaches collection code fails silently rather than loudly.

### Avoid monkey patching; use refinements or delegation

Reopening `String` or `Hash` in an application is a global mutation that leaks into every gem, cannot be un-loaded, and collides with other libraries' identical reopen. If a core-class extension is unavoidable, `refine` confines it:

```ruby
module MarkdownHelpers
  refine String do
    def to_heading_id
      downcase.gsub(/[^a-z0-9]+/, "-").delete_suffix("-")
    end
  end
end

using MarkdownHelpers
"Hello, World!".to_heading_id
```

Refinements are lexically scoped: they are active from the `using` call to the end of that file or module body, and invisible everywhere else unless that file also calls `using`. `using` cannot be called inside a method body (it raises), and code that reflects on the object (`respond_to?`, `method`) does not see refined methods unless you refine those too. That scope discipline is the point — it is why a refinement is a local decision and a reopen is a global one.

### Blocks, procs, and lambdas differ in arity and in `return`

| Form                     | Arity enforced                | `return` returns from | `break` in a block            |
| ------------------------ | ----------------------------- | --------------------- | ----------------------------- |
| `lambda { }` / `->`      | Yes                           | The lambda            | n/a (use `return`)            |
| `proc { }`               | No (nil-fills, ignores extra) | The enclosing method  | Enclosing method that yielded |
| Block passed to a method | No                            | The enclosing method  | The method that yielded       |

A `proc` with a missing argument receives `nil`, and a `lambda` raises `ArgumentError` — the same code, two behaviors, chosen by which constructor you typed. `return` inside a proc that outlives its defining method raises `LocalJumpError`. When the distinction matters, inspect instead of guessing:

```ruby
->(a, b) { a + b }.parameters   # => [[:req, :a], [:req, :b]]
proc { |a, b| }.parameters      # => [[:opt, :a], [:opt, :b]]
proc { |a, b| }.call(1, 2)      # => a == 1, b == 2; extra args are ignored
proc { |a, b| }.call(1)         # => a == 1, b == nil; missing args nil-fill
proc { |a, b| }.call([1, 2])    # => a == 1, b == 2; one Array argument is destructured
->(a, b) { a + b }.call(1)      # => ArgumentError: wrong number of arguments
->(a, b) { }.arity              # => 2 — a lambda's arity is its parameter count
```

`parameters` is the reliable introspection for both forms. A non-lambda proc's `arity` is not a substitute for it: because a single Array argument is destructured across the parameters, the same proc accepts a call shape its arity does not describe. Use `Proc#lambda?` to tell the two apart, and validate a callable against `parameters` (or `Method#parameters`) rather than discovering the mismatch in production. Argument splatting is the other half: a leading splat (`|*args, last|`) consumes the middle, so a block that must see both ends uses it rather than indexing into a collected array.

Modern enumerable vocabulary worth preferring over hand-rolled loops: `Enumerable#filter_map` (2.7), `Enumerable#tally` (2.7), `Hash#transform_values` (2.4), `Hash#transform_keys` (2.5), `Hash#except`/`Hash#slice` (3.0), `Array#intersection`/`#difference`/`#union` (2.6), `String#delete_prefix`/`#delete_suffix` (2.5), `Comparable#clamp` (2.4, Range argument since 2.7), `Object#then` (2.6), endless method definitions (3.0).

## Errors, Dependencies, and Tests

### Exception hierarchy and `retry`

`rescue` with no class rescues `StandardError` and its descendants only. `Exception` sits above that and includes `SystemExit`, `SignalException` (so Ctrl-C), `NoMemoryError`, and `ScriptError` — which contains `SyntaxError`, `LoadError`, and `NotImplementedError`. That last one matters: `NotImplementedError` is _not_ a `StandardError`, so `rescue => e` will not catch it, and `Lint/RescueException` exists precisely because `rescue Exception` swallows `exit` and interrupt signals.

```ruby
module Payments
  class Error < StandardError; end

  class Declined < Error
    attr_reader :code

    def initialize(code, message = "payment declined")
      @code = code
      super(message)
    end
  end
end

def charge(gateway, amount, attempts: 3)
  tries = 0

  begin
    tries += 1
    gateway.charge(amount)
  rescue Payments::Declined
    raise
  rescue Net::ReadTimeout, Errno::ECONNRESET
    raise Payments::Error, "gateway unreachable after #{tries} attempts" if tries >= attempts

    sleep(2**tries)
    retry
  end
end
```

The decline is re-raised untouched because retrying a declined card cannot succeed; only the transport errors are retried. Retrying a non-idempotent charge risks a double capture, so pair the retry with an idempotency key the gateway deduplicates on.

Custom error classes belong in the domain namespace (`Payments::Error`), not at top level, and should carry structured data (`code`) rather than encoding it in the message string. `raise "message"` raises `RuntimeError`, which is unclassifiable by a rescuer; always raise a named class.

`retry` re-executes the `begin` block, so anything mutated before the failure is still mutated — reset state or make the operation idempotent before retrying. Bound retries with a counter and back off; an unbounded `retry` on a hard failure is an infinite loop that pins a worker. `ensure` runs on `return`, `break`, and `next`, its return value is discarded, and a `return` inside `ensure` swallows the in-flight exception. When raising inside a `rescue`, `Exception#cause` is set automatically to the exception being handled; a bare `raise` re-raises the current exception with `cause` intact. `rescue` used as a modifier (`value = parse(x) rescue nil`) rescues `StandardError` and hides the failure at the point it happened — `Style/RescueModifier` flags it.

### Bundler discipline

`Gemfile` states intent; `Gemfile.lock` states the resolved graph and must be committed for applications (libraries conventionally gitignore it, since the consumer resolves). Version constraints use the pessimistic operator, whose semantics depend on how many segments you write: `~> 1.2` allows `>= 1.2, < 2.0`, while `~> 1.2.3` allows `>= 1.2.3, < 1.3.0`.

```ruby
source "https://rubygems.org"
ruby "3.4.1"

gem "rails", "~> 7.2"
gem "pg", "~> 1.5"
gem "csv", require: false

group :development, :test do
  gem "rspec-rails", "~> 7.1"
end
```

The `ruby` directive is written into the lock's `RUBY VERSION` section, and Bundler refuses to run under a different interpreter version — the cheapest way to keep CI, local, and production aligned. In CI, resolve deterministically:

```sh
bundle config set --local deployment true
bundle config set --local frozen true
bundle install --jobs 4 --retry 3
bundle exec rspec
```

`frozen` makes any Gemfile/lock drift a hard failure instead of a silent re-resolve, and `deployment` installs into `vendor/bundle` with the same effect on version resolution. On a machine, `bundle update some_gem` (single gem, `--conservative` to hold the rest) is the deliberate act; a bare `bundle update` re-resolves the entire graph and should be its own reviewed commit. Every Ruby invocation in scripts, CI, and `Procfile` goes through `bundle exec`, or a locally installed newer gem activates instead of the locked one (`Gem::LoadError` / "You have already activated"). Add platforms explicitly with `bundle lock --add-platform x86_64-linux` so a macOS lockfile does not break Linux CI.

### RSpec conventions

`describe` names the unit (use `described_class` inside), `context` names a state or input ("when the token is expired", "without a customer"), and `it` names the observable outcome. `RSpec/ContextWording` enforces the `when`/`with`/`without` prefixes that make a spec list readable as prose.

```ruby
RSpec.describe Invoice do
  subject(:invoice) { described_class.new(account:, due_on:) }

  let(:account) { instance_double(Account, currency: "USD") }
  let(:due_on) { Date.new(2026, 1, 31) }

  context "when the due date has passed" do
    let(:due_on) { Date.new(2020, 1, 1) }

    it { is_expected.to be_overdue }
  end
end
```

`let` is lazy and memoized per example, and a nested `let` with the same name overrides the outer one — that is the whole mechanism behind the example above. `let!` runs eagerly in a `before` hook in definition order, which makes it a side-effect declaration, not a convenience: `RSpec/LetSetup` flags a `let!` whose value is never referenced, because the setup it performs is invisible at the example. `before(:each)` is transactional in Rails; `before(:all)` runs once outside the transaction and leaks rows unless an `after(:all)` cleans up (`RSpec/BeforeAfterAll` warns). `let` is unavailable inside `before(:all)`.

Prefer `instance_double`/`class_double` over bare `double`: verifying doubles raise when the stubbed method does not exist on the class or the argument count is wrong, which is the difference between a mock and a lie. `allow_any_instance_of` (`RSpec/AnyInstance`) disables that verification across the whole object and should be treated as a smell.

Keep the failure-first loop cheap: `config.example_status_persistence_file_path = "spec/examples.txt"` in `spec_helper`, then `rspec --only-failures` (or `--next-failure` to stop at the first). Run `--seed` reporting on by default so an order-dependent failure is reproducible, and use `aggregate_failures` when several assertions describe one outcome instead of splitting them into meaningless examples. `RSpec/MultipleExpectations`, `RSpec/ExampleLength`, `RSpec/NestedGroups`, and `RSpec/MultipleMemoizedHelpers` bound the shape of a spec file; the defaults are deliberately tight, so raise a `Max` with a reason rather than disabling the cop.

### Metaprogramming: small and introspectable

`define_method` with a block captures the surrounding scope — block parameters get a fresh binding per invocation, so building methods in a loop captures distinct values (unlike `for`, which shares one binding). `method_missing` must be paired with `respond_to_missing?`, or `respond_to?` lies to every library that checks it; both are on the hot path for every unknown call, so a `define_method` loop or an explicit method is preferable whenever the set of names is known. `send` bypasses `private` and should be `public_send` unless the test or framework genuinely needs otherwise. `class_eval` with a string, `eval`, and `const_get` on user input are code-injection surfaces and should be treated as such.

## Performance Traps

| Trap                                               | Why It Costs                                                                                                  | Fix                                                                                  |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `str += x` in a loop                               | Allocates a new String per iteration; O(n²) bytes copied                                                      | `str << x` on a mutable buffer (`+""` or `String.new` under `frozen_string_literal`) |
| `"a" << "b"` under the frozen magic comment        | `FrozenError` — the literal is frozen                                                                         | `buffer = +""` then `<<`, or `String#join`/`Array#sum`                               |
| `list.select { }.first`                            | Walks the whole collection after finding a match                                                              | `list.detect { }` (alias `find`)                                                     |
| `list.sort` with a comparator block, then `.first` | Recomputes the sort key O(n log n) times                                                                      | `list.min_by(&:key)`; `sort_by` for full sorts (key computed once)                   |
| `array.include?(x)` in a loop                      | Linear scan per lookup                                                                                        | `Set` for membership, or `hash.key?(k)` instead of `hash.keys.include?(k)`           |
| `map { }.flatten(1)`                               | Intermediate array per element                                                                                | `flat_map`                                                                           |
| `OpenStruct` for records                           | `method_missing` per read, typo returns `nil`, leaving stdlib                                                 | `Data.define` / `Struct` / `Hash#fetch`                                              |
| Regexp literal in a hot loop with interpolation    | Recompiles per iteration                                                                                      | Hoist to a constant, or `Regexp.union` of static patterns                            |
| `freeze` assumed to cover literals                 | `# frozen_string_literal` freezes string literals only, not array/hash literals, and not interpolated strings | `.freeze` on collections; `Style/MutableConstant` catches the constant case          |

The Rails-specific trap is the N+1 query: iterating a relation and touching an association issues one query per row.

```ruby
orders = Order.where(status: "open").includes(:customer, :line_items)
orders.each { |o| puts o.customer.email }

Order.where(status: "open").each { |o| puts o.customer.email }   # N+1
```

`includes` chooses `preload` (one extra query per association) or `eager_load` (a single LEFT JOIN); filtering on the associated table requires `references(:customer)` so the join is chosen. `joins` does **not** load the association, so `joins(:customer).each { |o| o.customer }` is still N+1. Enable `strict_loading` on the model or in the console (`ActiveRecord::Base.strict_loading_by_default = true`, Rails 6.1+) to make a lazy load raise `ActiveRecord::StrictLoadingViolationError` instead of quietly querying, and add `bullet` or a subscriber to `ActiveSupport::Notifications` `sql.active_record` in the test suite to catch the ones that slip through. Also: `relation.count` always issues SQL, `size` uses a counter cache or the loaded collection, and `length` always loads; `pluck(:email)` skips AR instantiation where `map(&:email)` does not; `find_each` batches by primary key and ignores any `order`/`limit` you set on the relation; `update_all` and `insert_all` bypass validations and callbacks by design.

## Common Mistakes

| Mistake                                               | Why It Breaks                                                                 | Correct Approach                                                                                              |
| ----------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `rescue Exception => e`                               | Swallows `Interrupt`, `SystemExit`, and `NoMemoryError`; Ctrl-C stops working | `rescue => e` (StandardError) or name the specific classes; `Lint/RescueException`                            |
| `rescue` without re-raise or logging                  | Failure becomes a silent `nil` two call frames later                          | Rescue at the boundary, map to a domain error, log with the exception, re-raise if the caller cannot continue |
| `retry` with no counter or backoff                    | Unbounded loop against a failing dependency                                   | Bound attempts, exponential backoff, reset mutated state before retrying                                      |
| `attr_accessor` for every attribute                   | Any caller can violate the invariant the class exists to protect              | `attr_reader` publicly, `private attr_writer` internally, explicit setter when validation is needed           |
| `Struct` as a Hash key or shared record               | Mutable, and `==` also matches an equal Array                                 | `Data.define` for immutable value objects                                                                     |
| Reopening `String`/`Array` to add a helper            | Global mutation affecting every gem, unresolvable collisions                  | `refine` in a module, `using` at the one call site that needs it                                              |
| Positional `options = {}` parameter                   | Typos silently ignored; signature documents nothing                           | Required/optional keyword arguments, which raise `ArgumentError` on a bad key                                 |
| `payload["status"]` after `JSON.parse`                | String keys in one path, symbol keys in another, two lookups for one value    | `JSON.parse(body, symbolize_names: true)` and normalize once at the boundary                                  |
| `let!` for everything                                 | Setup order becomes load-bearing and invisible; specs slow down               | Lazy `let`, `let!` only when the side effect is the point (`RSpec/LetSetup`)                                  |
| `double("Account")` instead of a verifying double     | Stubbing a method that does not exist; the test passes while the code fails   | `instance_double(Account)`, `class_double`                                                                    |
| Committing a hand-edited `.rubocop_todo.yml`          | Debt list drifts from reality and never shrinks                               | Regenerate with `rubocop --auto-gen-config`; pay down cops and regenerate                                     |
| `bundle update` on a shared branch                    | Re-resolves the whole graph in one unreviewed commit                          | `bundle update some_gem --conservative`, or a dedicated dependency PR                                         |
| Assuming `# frozen_string_literal` freezes everything | Array/hash literals and interpolated strings stay mutable                     | `.freeze` constants explicitly; `Style/MutableConstant`                                                       |
| Iterating a relation and touching an association      | Lazy load fires one query per row — the N+1 problem                           | `includes(:customer)`; `references` when filtering on the association                                         |

## Checklist

1. Confirm `.rubocop.yml` is committed and lists `TargetRubyVersion` matching the Gemfile's `ruby` directive and the CI image.
2. Verify extensions load via `plugins:` (or a still-valid `require:`), and that `rubocop-performance` and `rubocop-rspec` are enabled where the tree needs them.
3. Run `rubocop --format offenses` and check the highest-count cops against `.rubocop_todo.yml`; regenerate the todo file with `--auto-gen-config` instead of editing it.
4. Grep for `rubocop:disable` and `rubocop:todo` and confirm each carries a reason on the same line; flag any `rubocop:disable all` or unreasoned disable.
5. Confirm CI runs `rubocop --force-exclusion --display-cop-names` with no `--ignore-disable-comments`, and that `.rubocop_cache` and `vendor/bundle` are gitignored.
6. Verify every `.rb` file that mutates string literals begins with `# frozen_string_literal: true` on line 1 (or line 2 after a shebang) and that no file sets it to `false`; check `Style/FrozenStringLiteralComment` uses `always_true`.
7. Audit naming with `rubocop --only Naming/MethodName,Naming/VariableName,Naming/ConstantName,Naming/MethodParameterName,Naming/PredicateName`.
8. List methods with a `!` suffix and confirm each has a non-`!` counterpart and mutates or raises as its name claims; confirm each `?` method returns a boolean.
9. Find trailing `= {}` or `options = {}` parameters and convert them to keyword arguments; confirm no caller still passes a bare Hash to a keyword-accepting method.
10. Locate every `Struct`, `Data.define`, and `OpenStruct` use; migrate `OpenStruct` and mutable shared `Struct` records to `Data.define`, and check nothing uses a mutable record as a Hash key.
11. Grep for `class String`, `class Array`, `class Hash`, `class Object`, and `module Kernel` reopens; replace them with `refine` modules or delegation.
12. Check `attr_accessor` usage against `attr_reader` and confirm public setters are deliberate; run `rubocop --only Style/TrivialAccessors`.
13. Grep for `rescue Exception`, bare `rescue`, `rescue` modifiers, and `retry`; verify retries are bounded with backoff and that custom errors subclass `StandardError` inside the domain namespace.
14. Verify `Gemfile.lock` is committed for applications (and gitignored for gems), that CI sets `frozen`/`deployment` before `bundle install`, and that every Ruby entry point uses `bundle exec`.
15. Inspect `Gemfile` version constraints for a missing pessimistic operator (`~>`) and confirm the `ruby` directive is present.
16. Audit specs for `let!` whose value is unused, bare `double`, `allow_any_instance_of`, and instance variables in examples; confirm verifying doubles are the default.
17. Check that `spec_helper` sets `example_status_persistence_file_path` and that random ordering is enabled, so `rspec --only-failures` works in the local loop.
18. Profile the hot paths for the loop-level traps above — `+=` string building, `select.first`, `include?` on arrays, `sort { }` — and confirm `frozen_string_literal` files build strings with `+""` or `String.new`.
19. Trace every association access inside an iteration in Rails models and controllers; confirm `includes`/`preload` is present, `joins` is not being used as a substitute, and `pluck`/`find_each`/`update_all` are used where the AR instantiation is unnecessary.
