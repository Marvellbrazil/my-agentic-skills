# Localization Testing and QA

Localization QA is the set of gates that prove a build actually renders correctly in every locale it claims to support.
The failures are almost never a missing translation: they are a hardcoded English string extraction never saw, a German
compound that overflows a fixed-width button, a date that shifts a day across a DST boundary, or a toast rendered as
tofu boxes because the CJK font was never bundled. None of these throw, so nothing fails until a user in the target
locale sees a broken screen. This module defines the gates — pseudolocalization, key auditing, a justified locale
matrix, frozen-clock time-zone tests, per-locale visual regression, and a CI job that renders every locale — that turn
those silent failures into red builds.

## When This Applies

- Before translation lands: you want layout, extraction, and truncation validated without waiting for a TMS round-trip.
- A new locale is added to `supportedLocales`, `knownRegions`, or Android `resourceConfigurations`.
- A bug report says "text is cut off", "the layout is mirrored wrong", or "the date is off by one".
- You are introducing or replacing a string-extraction pipeline, or switching TMS/vendor.
- Any component has a fixed width/height, a single-line label, or a `line-clamp`.
- You add a library that formats dates, numbers, plurals, or lists.
- You are setting up CI for an app that already ships more than one locale.
- You are auditing before a release that opens RTL, CJK, or non-Gregorian-calendar markets.
- A string is rendered from an attribute (`aria-label`, `title`, `alt`, `placeholder`, toast) rather than JSX text.

## Pseudolocalization: Layout and Extraction Proof Without Translators

Pseudolocalization generates a synthetic locale from your source strings. Two variants exist and they test different
things: an **accented + expanded** locale proves that layout survives longer text and that every visible string went
through the catalog, and a **bidi/mirrored** locale proves the UI flips for RTL.

| Ecosystem               | Accented / expanded             | Bidi / RTL                                                                       | How to enable                                                                                              |
| ----------------------- | ------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| ICU / CLDR data         | `en-XA`                         | `ar-XB`                                                                          | Generated by the CLDR-to-ICU tool; `en_XA` accents and expands, `ar_XB` inserts BiDi control characters    |
| Android (AGP 4.2+)      | `en-XA`                         | `ar-XB`                                                                          | `android.buildTypes.debug.pseudoLocalesEnabled true`, then select the pseudolocale in Settings → Languages |
| iOS / Xcode             | Double-Length Pseudolanguage    | Right-to-Left Pseudolanguage                                                     | Edit Scheme → Run → Options → Application Language                                                         |
| iOS / macOS launch args | `-NSDoubleLocalizedStrings YES` | `-AppleTextDirection YES` (macOS also `-NSForceRightToLeftWritingDirection YES`) | Scheme → Run → Arguments Passed On Launch                                                                  |
| FormatJS CLI            | `--pseudo-locale en-XA`         | `--pseudo-locale en-XB`                                                          | `formatjs compile lang/en.json --ast --pseudo-locale en-XA` (requires `--ast`)                             |
| Lingui                  | `pseudoLocale` in config        | same setting                                                                     | `compile` pseudo-localizes the locale that equals `pseudoLocale`                                           |

The detection mechanism is the important part. ICU's `en_XA` maps ASCII to accented look-alikes, pads the string so it
grows by at least 50% — not the 30% often quoted — and wraps each message unit in brackets: `"November"` becomes roughly
`[Ñöṽéɱƀéŕ one two]`. Therefore:

- A string that renders as **plain unaccented ASCII** never entered the catalog. It is hardcoded. This is the single most
  reliable hardcoded-string detector, and no lint rule replaces it.
- A sentence assembled from two catalog fragments renders as **two bracketed units** instead of one. That exposes
  concatenation and sentence-splitting, which are the failures described in [intl-pluralization.md](intl-
  pluralization.md).
- Text that is **clipped, ellipsized, or overflows** at 50% expansion will overflow in German, Finnish, or Hungarian.

Android specifics: `pseudoLocalesEnabled` is a _debug_ build-type property, and AGP generates `en-XA` and `ar-XB`
resources into the APK. If they are missing, check `resourceConfigurations` — it silently strips locales it does not
list.

```groovy
android {
    buildTypes {
        debug { pseudoLocalesEnabled true }
        release { pseudoLocalesEnabled false }
    }
}
```

## Automated String and Key Auditing

Lint the _source_, not the rendered page. These checks run in milliseconds and fail the build before a screenshot job starts.

**ICU syntax and extraction rules (ESLint, `eslint-plugin-formatjs`).** The plugin ships two shareable configs,
`formatjs.configs.recommended` and `formatjs.configs.strict`, and covers both React (`FormattedMessage`,
`intl.formatMessage`, `defineMessages`) and Vue (`$formatMessage` in SFCs). The rules that matter for QA:

| Rule                                   | What it catches                                                           |
| -------------------------------------- | ------------------------------------------------------------------------- |
| `formatjs/no-invalid-icu`              | `defaultMessage` that does not parse as ICU MessageFormat                 |
| `formatjs/no-literal-string-in-jsx`    | Untranslated string literals in JSX                                       |
| `formatjs/no-literal-string-in-object` | Untranslated string literals in object properties                         |
| `formatjs/enforce-plural-rules`        | A plural message missing required CLDR categories                         |
| `formatjs/enforce-default-message`     | A message descriptor with no `defaultMessage`                             |
| `formatjs/enforce-description`         | A message with no translator context (option `minLength`, mode `literal`) |
| `formatjs/enforce-placeholders`        | A placeholder declared in the message but not passed at the call site     |
| `formatjs/enforce-id`                  | Inconsistent message IDs across catalogs                                  |
| `formatjs/no-complex-selectors`        | Flattened sentence count above the limit (default `20`)                   |
| `formatjs/blocklist-elements`          | Elements your vendor cannot handle, e.g. `selectordinal`                  |

```json
{
  "plugins": ["formatjs"],
  "rules": {
    "formatjs/no-invalid-icu": "error",
    "formatjs/no-literal-string-in-jsx": "error",
    "formatjs/no-literal-string-in-object": "error",
    "formatjs/enforce-plural-rules": "error",
    "formatjs/enforce-description": ["error", { "minLength": 10 }]
  }
}
```

Validating ICU at build time matters because the alternative is a runtime crash or a raw message key rendered to the
user. A plural missing its `other` branch is a build error here, not a production incident.

**Unused and missing keys.** Extraction tools accumulate dead keys after refactors. `i18n-unused` reports both directions and can fail CI:

```bash
npx i18n-unused display-unused --fail-on-unused
npx i18n-unused display-missed --fail-on-missed
```

Its `translationKeyMatcher` defaults to matching `$_`, `$t`, `t`, `$tc`, `tc`, and `i18nKey`; `ignoreComments` skips
commented-out keys. Lingui covers the same ground inside its own CLI: `lingui extract --clean` removes obsolete
messages, and `lingui compile --strict` fails when a catalog has missing translations.

**Per-framework untranslated reports.** Flutter writes a machine-readable gap file via `flutter gen-l10n --untranslated-
messages-file=untranslated.json`, emitting `{"de": ["greeting", "cartTotal"], "ar": []}`, which is trivial to gate on.

**Coverage metrics in Python.** Babel exposes exactly what you need, including the `obsolete` flag on messages:

```python
from babel.messages.pofile import read_po

with open("locale/ar/LC_MESSAGES/messages.po", "rb") as fh:
    catalog = read_po(fh)

translated = fuzzy = untranslated = 0
for message in catalog:
    if message.id == "" or getattr(message, "obsolete", False):
        continue
    if message.fuzzy:
        fuzzy += 1
    elif message.string:
        translated += 1
    else:
        untranslated += 1

total = translated + fuzzy + untranslated
pct = 100.0 * translated / total if total else 100.0
print(f"{catalog.locale}: {pct:.1f}% ({untranslated} missing)")
```

`Catalog.num_plurals` gives the expected plural count for the locale — `6` for `ar`, `2` for `fr` — a cheap check that
the catalog header's `Plural-Forms` is not lying. For a vendor-facing report, `pocount --csv` from translate-toolkit
emits per-file translated/fuzzy/untranslated string and word counts directly.

**What static analysis cannot see.** Dynamic keys such as ``t(`cart.${status}.label`)`` are invisible to every extractor
and every lint rule above, as are strings built by concatenation. This is why the pseudolocale pass is not optional: it
is the only check that observes what actually reached the screen.

## The Locale Test Matrix

A matrix is not "every locale we ship". It is the smallest set of locales that each exercise a distinct failure class.
Six to ten is the practical ceiling; beyond that you are paying CI minutes to re-test English behaviour.

| Slot                   | Why it earns a slot                                        | Candidate locales                                                                                                               | What it catches                                                    |
| ---------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Base / LTR             | Control; must stay green                                   | `en`, `de`                                                                                                                      | Regressions in the reference rendering                             |
| Long-word              | Compounds and agglutination overflow fixed widths          | `de`, `fi`, `hu`, `tr`                                                                                                          | Truncation; `tr` also breaks naive `toLowerCase` on `I`/`i`        |
| RTL                    | Mirrored layout, bidi runs, logical properties             | `ar-EG`, `he`, `fa`, `ur`                                                                                                       | Unmirrored icons, wrong scroll origin, mixed-direction punctuation |
| CJK                    | No inter-word spaces, different line breaking, large fonts | `ja`, `zh-Hans`, `ko`                                                                                                           | Line-break rules, font weight/height, missing glyphs               |
| Plural-heavy           | Exercises every CLDR category                              | `ar` (6), `cy` (6), `ga` (5), `mt` (5), `ru`/`pl`/`cs` (4)                                                                      | Missing `few`/`many`/`two` branches                                |
| Non-Latin numerals     | Default numbering system is not `latn`                     | `ar-EG`→`arab`, `fa`→`arabext`, `bn`→`beng`, `mr`/`ne`→`deva`, `my`→`mymr`                                                      | Latin digits leaking from a hardcoded formatter                    |
| Non-Gregorian calendar | Year and month arithmetic differ                           | `th-TH`, `fa`, `ar-SA`                                                                                                          | Wrong year, wrong month name                                       |
| Fractional offset      | Offsets are not whole hours                                | `Asia/Kathmandu` (+05:45), `Australia/Eucla` (+08:45), `Pacific/Chatham` (+12:45/+13:45), `Australia/Lord_Howe` (+10:30/+11:00) | Naive `offset * 60` maths, wrong minute rendering                  |

Three entries are counter-intuitive enough to state outright, because getting them wrong produces a test that passes while the product is broken:

- **`hi`, `th`, `ta`, and `ur` default to `latn` digits.** `new Intl.NumberFormat('ar-
  EG').resolvedOptions().numberingSystem` returns `'arab'`, but the same call for `'hi'` returns `'latn'`. Pick `ar-
  EG`/`fa`/`bn`/`mr`/`my` when you need non-Latin numerals.
- **Russian and Czech now have four plural categories**, not three: CLDR added `many` for decimals, so `new
  Intl.PluralRules('ru').resolvedOptions().pluralCategories` returns `["one","few","many","other"]`. A catalog authored
  against the older three-category model will fail `formatjs/enforce-plural-rules`. The categories themselves belong to
  [intl-pluralization.md](intl-pluralization.md).
- **Some locales have no `other`-only shape at all**: `ar` and `cy` carry six categories, `ga` and `mt` five. A single
  `one`/`other` message is only valid for the locales that actually have two.

Every locale in the app's `supportedLocales` must be one the matrix covers or explicitly delegates to a covered one.

## Clock, Time Zone, and Intl Fidelity

Time-zone bugs are two independent variables — the **zone** and the **instant** — and freezing only one of them is the most common CI mistake. Freeze both.

Playwright's Clock API is installed per `BrowserContext`, so one clock governs every page and iframe:

```ts
import { test, expect } from "@playwright/test";

test.use({ locale: "de-DE", timezoneId: "Europe/Berlin" });

test("shipping window across the DST gap", async ({ page }) => {
  await page.clock.install({ time: new Date("2026-03-08T06:30:00Z") });
  await page.goto("/checkout");
  await page.clock.pauseAt(new Date("2026-03-08T07:30:00Z"));
  await expect(page.getByTestId("date")).toHaveText("9. März 2026");
});
```

- `clock.setFixedTime` pins `Date.now()` and `new Date()` while leaving timers running — use it when you only need a stable instant.
- `clock.install` must be called before any other clock call; calling it after `setTimeout` or `setInterval` has been touched is undefined behaviour.
- `clock.setSystemTime` shifts the clock **without firing timers**, which is precisely the tool for a DST transition or a timezone change mid-session.
- `clock.fastForward` jumps and fires due timers at most once (laptop-lid semantics); `clock.runFor` ticks through and fires everything.
- `timezoneId` and `locale` on the context emulate the _browser_, not the test runner. Set `TZ` in the environment to move the runner itself.

Python equivalents, with the zone explicit:

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo
from freezegun import freeze_time

@freeze_time("2026-11-01 06:30:00", tz_offset=0)
def test_ambiguous_local_hour():
    instant = datetime(2026, 11, 1, 6, 30, tzinfo=timezone.utc)
    ny = instant.astimezone(ZoneInfo("America/New_York"))
    assert ny.hour == 1
    assert ny.fold == 1
```

Use real transition instants, not invented ones. In 2026, for `America/New_York`:

| UTC instant            | Local result | Why it matters                                          |
| ---------------------- | ------------ | ------------------------------------------------------- |
| `2026-03-08T06:30:00Z` | `01:30 EST`  | Last hour before the spring-forward gap                 |
| `2026-03-08T07:30:00Z` | `03:30 EDT`  | `02:30` local **does not exist**; naive code invents it |
| `2026-11-01T05:30:00Z` | `01:30 EDT`  | First pass through the ambiguous hour (`fold=0`)        |
| `2026-11-01T06:30:00Z` | `01:30 EST`  | Second pass through the same wall-clock hour (`fold=1`) |

**Test against real locale data, never a mock.** Mocking `Intl` is the single most effective way to ship a broken
localization test: the mock encodes your assumption, so the test can only confirm it. Two traps make this concrete:

- **Unsupported tags fall back silently.** `new Intl.NumberFormat('zz').resolvedOptions().locale` returns `id-ID` on a
  full-ICU runtime; `new Intl.NumberFormat('en-XX')` returns `en`. Nothing throws. A test using a placeholder locale
  asserts against the wrong locale and passes. Assert `Intl.NumberFormat.supportedLocalesOf(['ar-EG', 'zz'])` returns
  `['ar-EG']` before relying on a tag.
- **The runtime may not carry the data you think.** Node can be built with `small-icu` (English only). Log
  `process.versions.icu` and `process.versions.cldr` in CI so a data downgrade is visible.

Text direction is queryable rather than hardcoded: `new Intl.Locale('ar').getTextInfo().direction` returns `'rtl'`, and
`'en'` returns `'ltr'`. `getTextInfo()` is Baseline 2026; in some older browser versions it was an accessor property
named `textInfo`, so feature-detect rather than assuming either shape. Directionality semantics are covered in [intl-
bidi.md](intl-bidi.md).

## Visual Regression, Accessibility, and the CI Gate

**Screenshots per locale.** A visual diff is only meaningful if the frame is deterministic: freeze the clock, fix the
viewport, seed the data, and disable animation. Store one baseline directory per locale so a German overflow does not
mask an Arabic mirroring bug.

```ts
import { test, expect } from "@playwright/test";

const locale = process.env.LOCALE ?? "en-US";

test.use({ locale, timezoneId: process.env.TZ_ID ?? "UTC" });

test("no clipped text", async ({ page }) => {
  await page.clock.setFixedTime(new Date("2026-03-08T07:30:00Z"));
  await page.goto("/");
  await expect(page).toHaveScreenshot(`${locale}-home.png`);
  const clipped = await page
    .locator("[data-overflow-check]")
    .evaluateAll((n) =>
      n
        .filter((e) => e.scrollWidth > e.clientWidth + 1)
        .map((e) => e.textContent),
    );
  expect(clipped).toEqual([]);
});
```

The overflow assertion is the part that generalizes: it catches truncation in locales you did not screenshot, and it is
a hard pass/fail rather than a pixel diff a reviewer must interpret.

**Screenshot review for translators.** A screenshot per screen per locale, attached to the translation task, is the only
context that lets a translator see whether their string fits and reads naturally in place. Generate them from the same
Playwright run that produces the baselines so the reviewed artifact and the gated artifact are identical.

**RTL verification without being an RTL speaker.** Use the bidi pseudolocale and check structural invariants rather than reading the text:

- `dir` is set on `<html>`, not on a wrapper div — a wrapper leaves scrollbars, modals, and portals in LTR.
- Layout uses logical properties (`margin-inline-start`, `padding-inline-end`, `inset-inline`) rather than `left`/`right`.
- Directional icons mirror (back arrows, chevrons, progress indicators); non-directional icons do **not** (clocks, media transport, logos, checkmarks).
- Mixed-direction runs render with punctuation on the correct side.

**Missing glyphs (tofu).** Text that renders as `□□□` is a font-coverage bug, and it is detectable at build time:

```js
import fontkit from "fontkit";

export function missingGlyphs(fontPath, sample) {
  const font = fontkit.openSync(fontPath);
  return [...sample]
    .map((ch) => ch.codePointAt(0))
    .filter((cp) => cp > 0x20 && !font.hasGlyphForCodePoint(cp));
}
```

`font.hasGlyphForCodePoint(codePoint)` is a direct coverage test; `font.characterSet` gives the full supported set for a
preflight assertion. Run it for every font in the bundle against a sample string per matrix locale and treat any hit as
a build failure. In the browser, `document.fonts.check()` only tells you whether a font is loaded for some text — it
does not verify that a specific glyph exists.

**Accessibility checks that vary by locale.**

- Every inline foreign-language run carries its own `lang`, so a screen reader switches voice: `<span lang="en">Wi-
  Fi</span>` inside Arabic content. This is WCAG 3.1.2 (Language of Parts).
- The document's `lang` and `dir` must match the active locale, and both must update when the user switches language without a reload.
- `aria-label`, `title`, `alt`, and `placeholder` are user-visible strings, frequently missed by JSX-text extraction; lint them separately.
- Reading order and focus order follow `dir`; verify tab order in the bidi pseudolocale rather than trusting the visual layout.
- Re-run the matrix at 200% text zoom — the same components that overflow under `en-XA` fail here too.

**The CI job.** Split the pipeline into a fast static job and a slower render job that fans out across the matrix.

```yaml
jobs:
  static:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npx eslint .
      - run: npx i18n-unused display-missed --fail-on-missed
  locales:
    runs-on: ubuntu-latest
    needs: static
    strategy:
      fail-fast: false
      matrix:
        include:
          - { locale: en-XA, tz: UTC }
          - { locale: ar-XB, tz: Asia/Riyadh }
          - { locale: de-DE, tz: Europe/Berlin }
          - { locale: ar-EG, tz: Africa/Cairo }
          - { locale: ja-JP, tz: Asia/Tokyo }
          - { locale: ru-RU, tz: Europe/Moscow }
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npx playwright test
        env:
          LOCALE: ${{ matrix.locale }}
          TZ_ID: ${{ matrix.tz }}
          TZ: UTC
```

`fail-fast: false` matters — you want the full set of failing locales from one run, not just the first. `TZ: UTC` pins
the runner so the matrix varies the browser zone only.

**What to gate on.** Gate the two categories differently, because you control one and not the other:

| Gate                                                      | Threshold                                | Rationale                                                                        |
| --------------------------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------------------- |
| Hardcoded strings, ICU validity, missing glyphs, overflow | Zero                                     | Entirely within the team's control; any occurrence is a defect                   |
| Pseudolocale render                                       | 100% of screens                          | Also fully controlled                                                            |
| Missing keys in the source locale                         | Zero, or a delta against the base branch | Source strings are authored here                                                 |
| Translated coverage per target locale                     | A delta, not an absolute percentage      | An absolute floor blocks unrelated merges while a vendor round-trip is in flight |

An absolute `100% translated` gate is the most common misconfiguration: it converts a translation backlog, which is a
business decision, into a merge blocker. Compare against the base branch instead and fail only when coverage drops or
new keys arrive untranslated.

## Common Mistakes

| Mistake                                                                 | Why It Breaks                                                                                                                                | Correct Approach                                                                                            |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Mocking `Intl` / `Intl.DateTimeFormat` in tests                         | The mock encodes your assumption, so the test can only confirm it; real CLDR data never runs                                                 | Use the real runtime and assert against real output; record `process.versions.icu` in CI                    |
| Using a placeholder locale like `zz` or `xx`                            | `Intl.NumberFormat('zz').resolvedOptions().locale` silently returns `id-ID`; the test asserts against the wrong locale and passes            | Assert `supportedLocalesOf` first, then use a locale the runtime actually carries                           |
| Freezing the clock but not the zone (or vice versa)                     | Half the inputs to a date bug are still live; the test is flaky across machines                                                              | Freeze the instant and set `timezoneId`/`TZ` explicitly in the same fixture                                 |
| Assuming `hi`, `th`, `ta`, `ur` use non-Latin digits                    | Their CLDR default numbering system is `latn`; a test expecting Devanagari or Thai digits fails for the wrong reason, or a "fix" breaks them | Query `resolvedOptions().numberingSystem` and pick `ar-EG`/`fa`/`bn`/`mr`/`my` for non-Latin digits         |
| Treating Russian/Czech as three-category plural languages               | CLDR added `many`; `Intl.PluralRules('ru').resolvedOptions().pluralCategories` returns four entries                                          | Re-extract plural rules against current CLDR and enable `formatjs/enforce-plural-rules`                     |
| Gating CI on an absolute 100% translated threshold                      | Turns a translation backlog into a merge blocker on unrelated changes                                                                        | Gate source-side checks at zero and target coverage as a delta against the base branch                      |
| Skipping pseudolocalization because lint rules are enabled              | Lint only sees static literals; dynamic keys and concatenation are invisible to it                                                           | Run the `en-XA` pass in CI; plain unaccented text on screen is the hardcoded-string signal                  |
| Assuming expansion is 30%                                               | ICU's `en_XA` pads by at least 50%, and short strings and compounds exceed that                                                              | Test at 50% minimum and budget for more on short labels and long-word locales                               |
| Assuming all time zones are whole hours                                 | `Asia/Kathmandu` is +05:45, `Australia/Eucla` +08:45, `Pacific/Chatham` +12:45, `Australia/Lord_Howe` +10:30                                 | Include one fractional-offset zone and never multiply an offset by 60 to get minutes                        |
| Rendering screenshots without freezing the clock or animation           | Baselines diff on every run and get disabled or blindly re-approved                                                                          | Freeze the clock, fix the viewport, seed data, disable animation, store one baseline per locale             |
| Leaving pseudolocales in the release build                              | `en-XA`/`ar-XB` resources ship to users and appear in language pickers                                                                       | Keep `pseudoLocalesEnabled` on `debug` only; verify `resourceConfigurations` does not strip them from debug |
| Treating `ar-XB`/`en-XB` as the accented locale                         | In ICU `en_XA` is accented+expanded and `ar_XB` is bidi; FormatJS repurposed `en-XB` for bidi                                                | Use `en-XA` for layout/expansion and `ar-XB` (or `en-XB` in FormatJS) for mirroring                         |
| Letting `aria-label`, `title`, `alt`, and `placeholder` skip extraction | They are user-visible strings but not JSX text, so JSX-oriented lint and extraction miss them                                                | Lint them explicitly and include them in the pseudolocale review                                            |

## Checklist

1. Enable pseudolocalization in the debug build (`pseudoLocalesEnabled` / Xcode Application Language / `formatjs --pseudo-
   locale`) and confirm every screen shows accented, bracketed text.
2. Walk every screen under the pseudolocale and treat any plain unaccented ASCII string as a hardcoded-string defect.
3. Verify no text is clipped, ellipsized, or overflowing at 50% expansion, including single-line labels, buttons, tabs, and toasts.
4. Run the extraction linter with `formatjs/no-literal-string-in-jsx`, `formatjs/no-literal-string-in-object`, and `formatjs/no-invalid-icu` set to `error`.
5. Enable `formatjs/enforce-plural-rules` and re-verify every plural against current CLDR categories for its locale.
6. Run `i18n-unused display-missed --fail-on-missed` (or `lingui compile --strict`) and confirm zero keys referenced in code are absent from the catalogs.
7. Run `i18n-unused display-unused` (or `lingui extract --clean`) and remove keys no longer referenced in source.
8. Confirm `flutter gen-l10n --untranslated-messages-file` emits `{}` for the source locale, or gate the delta explicitly.
9. Freeze both the instant and the time zone in every time-dependent test, and assert the runner's `TZ` is set.
10. Test the spring-forward gap and the fall-back overlap at real UTC instants, and confirm the app never renders a non-existent local hour.
11. Assert `Intl.*.supportedLocalesOf(appLocales)` returns every supported locale, and log `process.versions.icu` in CI output.
12. Confirm the locale matrix contains at least one locale for each slot: long-word, RTL, CJK, plural-heavy, non-Latin-numeral, and fractional-offset.
13. Capture a screenshot per matrix locale with a frozen clock and fixed viewport, and run the `scrollWidth >
clientWidth` overflow assertion on every text container.
14. Run the missing-glyph check for every bundled font against a sample string per matrix locale, and fail the build on any hit.
15. Verify `<html>` carries both `lang` and `dir`, and that inline foreign-language runs carry their own `lang`.
16. Verify `aria-label`, `title`, `alt`, and `placeholder` strings are extracted, translated, and present in the pseudolocale pass.
17. Confirm pseudolocale resources are absent from the release artifact and present in debug.
18. Record the translated-coverage number per locale in the build output and fail only when it regresses against the base branch.
