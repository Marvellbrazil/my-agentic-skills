# Mobile performance

Source group 9. Tailored for native (iOS Swift/Obj-C, Android Kotlin/Java) and cross-platform mobile applications (React Native, Flutter, Expo). Mobile clients operate under strict memory, battery, and UI thread constraints where blocking operations cause visible jank or OS termination. Do not apply mobile-only profiling tools to pure web applications without explanation. Use [SKILL.md](../SKILL.md) for reporting.

| ID | Source item | Applicability, interpretation and evidence to seek |
| ----- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MP-01 | Compress image assets | Asset bundle and network optimization. Verify bundled image assets and remote downloads use modern compressed formats (WebP, HEIC, PNGcrush/OptiPNG) with appropriate DPI densities (@1x, @2x, @3x). Related: WL-20, WP-04. |
| MP-02 | Lazy-load off-screen views | Memory and view hierarchy efficiency. Inspect tab navigators, modal stacks, and view pagers to ensure off-screen screens and heavy subviews are unmounted or lazily instantiated until needed. Related: WP-16. |
| MP-03 | Cache API responses | Offline tolerance and network efficiency. Inspect client HTTP cache (URLCache, OkHttp cache, TanStack Query, RTK Query) to cache idempotent GET responses with disk persistence and sensible TTLs. Related: WP-01. |
| MP-04 | Paginate long lists | Client memory and render safety. Verify feeds, lists, and search results load in bounded batches (e.g. 20–50 items) with infinite scroll or pagination rather than loading thousands of items into memory simultaneously. Related: WP-11. |
| MP-05 | Debounce search input | Network and UI thread preservation. Inspect text input handlers in search bars to verify debounce/throttle logic (e.g. 300ms) prevents triggering API calls or database searches on every character typed. Related: WP-08. |
| MP-06 | Reduce main-thread work | UI responsiveness (60/120 FPS). Audit UI/main thread execution for heavy computations, complex cryptography, disk I/O, or blocking synchronization. Offload intensive logic to background threads/queues (DispatchQueue, Coroutines, Web Workers). |
| MP-07 | Preload critical data | Perceived launch and transition speed. Inspect app launch sequence and navigation flows to ensure critical user profile or initial feed cache is preloaded from local storage concurrently before screen transitions. |
| MP-08 | Remove unused dependencies | App binary footprint. Audit CocoaPods, SPM, Gradle dependencies, or `package.json` to eliminate unused native SDKs or heavy libraries that inflate download size and increase memory overhead. Related: AH-01, WP-18. |
| MP-09 | Defer non-critical work | Launch time optimization. Inspect app launch (`didFinishLaunchingWithOptions`, `Application.onCreate`, root component mount) to defer analytics SDK initialization, push token registration, and background sync until after initial UI render. Related: MP-20. |
| MP-10 | Add loading skeletons | Perceived performance. Inspect asynchronous screens for animated skeleton components or lightweight content previews while fetching data, preventing blank flash screens. Related: DC-15, WL-12, WP-05. |
| MP-11 | Fix N+1 queries | Local and remote database efficiency. Inspect local SQLite/Room/CoreData/Realm queries or remote GraphQL queries to ensure batch fetching or relational joins are used instead of querying child entities in loops. Related: WP-07. |
| MP-12 | Index the local database | Local persistence optimization. Inspect SQLite/Room/CoreData/WatermelonDB schema for indexes on primary search columns, foreign keys, and sorting fields to avoid full table scans on mobile storage. Related: WP-03. |
| MP-13 | Batch network requests | Radio power and latency reduction. Inspect API communication for batching mechanisms (GraphQL batching, composite REST endpoints) that consolidate multiple round-trips into a single network connection, saving device battery. |
| MP-14 | Recycle list cells | List scroll performance. Verify virtualized list components are used (UITableView, UICollectionView, RecyclerView, FlashList, FlatList) with properly configured reusable cell identifiers and lightweight row views. |
| MP-15 | Downsample big images | Memory preservation (OOM prevention). Ensure images loaded from disk or network are decoded directly to target display dimensions (downsampled/thumbnail decoding) rather than loading full-resolution multi-megapixel bitmaps into RAM. Related: WP-04. |
| MP-16 | Cancel in-flight requests | Resource cleanup. Inspect network tasks, search queries, and view unmount hooks to ensure pending in-flight HTTP requests and animations are explicitly cancelled when a user navigates away or types a new query. |
| MP-17 | Move parsing off-main | UI thread safety. Inspect large JSON, XML, or binary serialization/deserialization logic to ensure parsing takes place on background dispatch queues/threads rather than blocking the main UI thread. |
| MP-18 | Compress API payloads | Mobile network efficiency. Verify that mobile HTTP clients include `Accept-Encoding: gzip, br` headers and that API servers compress responses, conserving user cellular data and reducing latency. Related: WP-13. |
| MP-19 | Profile with Instruments | Empirical runtime verification. Profile the mobile application on physical test devices using Xcode Instruments (Time Profiler, Allocations, Leaks) or Android Studio Profiler (CPU, Memory). Never claim this has passed without actual profile traces. |
| MP-20 | Trim app launch time | Cold start optimization. Measure and optimize cold launch duration (time to first interactive frame). Target <400ms on modern physical devices by minimizing dynamic framework linking, static initializers, and synchronous launch blocking. |

## Supporting guidance

- Hardware constraints (RAM, thermal throttling, cellular radio power states) require empirical testing on physical target devices; simulator metrics do not reflect real-world battery and memory behavior.
