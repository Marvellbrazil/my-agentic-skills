# Website quality signals

Source group 10. Focuses on technical SEO, metadata completeness, crawler hygiene, and indicators of incomplete prototype boilerplate ("vibecoded giveaways"). Distinguish genuine functional bugs (like console errors or missing accessibility attributes) from intentional developer choices (like deliberate AI crawler blocking or custom branding). Use [SKILL.md](../SKILL.md) for reporting status.

| ID | Source item | Applicability, interpretation and evidence to seek |
| ----- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WQ-01 | vercel.app url | Deployment domain branding. Check whether the site runs on a platform staging subdomain (e.g. `*.vercel.app`, `*.netlify.app`, `*.pages.dev`) or a configured custom domain. Staging/preview subdomains are appropriate for pre-launch testing; commercial production launches typically require an owned custom domain. Advisory branding choice unless custom domain was contracted. |
| WQ-02 | viewsource empty | Client-rendered SPA check. Inspect initial server response HTML: if view-source shows only an empty `<div id="root"></div>` without semantic markup or metadata, evaluate SEO and crawler impact. For private authenticated dashboards, an SPA is completely acceptable; for public marketing and content sites, SSR/SSG/prerendering is recommended. |
| WQ-03 | no 404 page | Missing custom error page. Verify that navigating to a non-existent URL renders an intentional, branded 404 page with return navigation and returns an HTTP 404 status code (rather than blank white screens or redirecting to home without explanation). Cross-reference: WL-01. |
| WQ-04 | vite + react browser | Unchanged starter boilerplate. Inspect HTML `<title>` tag and default favicon to verify generic framework defaults (e.g., "Vite + React", "Create Next App", "Vite App", generic Vite/React SVGs) have been replaced with the product's actual identity. |
| WQ-05 | same page titles | Generic or duplicate document titles. Inspect multiple distinct routes to ensure each page has a unique, descriptive `<title>` tag reflecting its specific content (e.g., "Pricing - Acme" vs "Dashboard - Acme") rather than a static site-wide title everywhere. Cross-reference: WL-03. |
| WQ-06 | no meta desc | Search snippet optimization. Inspect HTML `<head>` for `<meta name="description" content="...">` tailored to each indexable page. Missing meta descriptions reduce click-through quality in search results. Cross-reference: WL-04. |
| WQ-07 | no og:image | Social preview cards. Inspect Open Graph tags (`<meta property="og:image" content="...">` and `<meta name="twitter:image" content="...">`) to ensure shared links display a branded, high-resolution preview card (1200x630px recommended). Cross-reference: WL-05. |
| WQ-08 | no structured data | Search enhancement. Check for Schema.org JSON-LD markup (`<script type="application/ld+json">`) defining Organization, WebSite, Product, or FAQ metadata where search rich snippets are desired. Advisory SEO enhancement. |
| WQ-09 | multiple H1's | Document outline and hierarchy. Inspect page markup for multiple `<h1>` elements. While HTML5 permits multiple H1s within separate sections, standard accessibility and SEO practice recommends a single, primary `<h1>` per page summarizing the page topic. Related: WQ-10. |
| WQ-10 | no H1's | Missing main heading. Verify every content page contains at least one descriptive `<h1>` tag to serve as the top-level landmark for assistive technologies and search indexing. |
| WQ-11 | no canonical tag | Duplicate content prevention. Inspect `<link rel="canonical" href="...">` tags to ensure self-referencing canonical URLs are defined, preventing duplicate indexing across query parameters, trailing slashes, or HTTP/HTTPS variants. |
| WQ-12 | no llms.txt | Emerging AI web index standard. Check whether an `/llms.txt` file exists summarizing site purpose, APIs, and key markdown documentation for AI agent ingestion. Advisory/optional; never treat a missing `llms.txt` as a release blocker. |
| WQ-13 | Al blocked robots.t | Crawler policy check (original text: Al blocked robots.t). Inspect `robots.txt` for disallow directives affecting AI user-agents (e.g., `GPTBot`, `ClaudeBot`, `PerplexityBot`). Verify whether blocking AI crawlers was an intentional owner decision (content protection/copyright) or accidental; preserve deliberate owner policies. Cross-reference: WL-07. |
| WQ-14 | no favicon | Browser identity and bookmarking. Inspect `<head>` for `<link rel="icon" ...>` and `<link rel="apple-touch-icon" ...>` pointing to real, branded icons. Cross-reference: WL-06. |
| WQ-15 | no sitemap.xml | Crawler discoverability. Verify that an accessible `/sitemap.xml` exists containing valid, canonical URLs with appropriate lastmod timestamps for all public indexable routes. Cross-reference: WL-08. |
| WQ-16 | no lang attributior | Accessibility and localization (original text: no lang attributior). Verify `<html lang="en">` (or appropriate ISO language code) is defined on the root `<html>` element so screen readers pronounce content with correct pronunciation and speech synthesizers. |
| WQ-17 | missing alt text | Accessibility baseline. Verify that all `<img>` tags possess an `alt` attribute (descriptive text for informative images, null `alt=""` for purely decorative images). Completely missing `alt` attributes violate WCAG 1.1.1. Cross-reference: WL-09, LP-09. |
| WQ-18 | source maps | Production bundle security and privacy. Check whether production `.map` source map files are uploaded to public web servers. Publicly exposed source maps reveal original source code, internal comments, and file structures. Recommended to keep private or upload only to error-tracking services (e.g., Sentry). |
| WQ-19 | console errors | Runtime stability. Inspect browser developer console during page load and key interactions for unhandled JavaScript exceptions, failed 404 network requests, or Content Security Policy violations. Production apps should render cleanly without console errors. |
| WQ-20 | massive JS bundle | Frontend performance. Analyze production JavaScript bundle size. Uncompressed initial client bundles exceeding 500 KB to 1 MB delay interactivity on mobile networks; optimize via code splitting, tree shaking, and dynamic imports. Cross-reference: WP-09, WP-15. |

## Supporting guidance

- Differentiate superficial polish from functional blockers: an unconfigured custom domain (`WQ-01`) is a business launch milestone, whereas broken console errors (`WQ-19`) or missing `lang` attributes (`WQ-16`) represent functional and accessibility defects.
