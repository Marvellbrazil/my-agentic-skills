# Web performance

Source group 8. Covers backend efficiency, database optimization, network caching, asset delivery, and frontend rendering performance for web applications. Assess performance based on actual measurements and workload characteristics rather than applying aggressive architectural changes blindly. Use [SKILL.md](../SKILL.md) for status reporting.

| ID | Source item | Applicability, interpretation and evidence to seek |
| ----- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WP-01 | Cache API responses | Caching strategy. Inspect HTTP caching headers (`Cache-Control: public, max-age=...`, `ETag`, `stale-while-revalidate`) for static or shared dynamic endpoints. Ensure authenticated, user-specific, or sensitive responses use `Cache-Control: no-store, private` to prevent cross-user data leakage. Related: MP-03. |
| WP-02 | Load balancer | Infrastructure scaling. Inspect deployment architecture for multi-instance reverse proxies or load balancers (e.g. AWS ALB, Cloudflare, NGINX) with health checks. For single-instance low-traffic prototypes, document as an infrastructure scaling consideration rather than a mandatory pre-launch blocker. |
| WP-03 | Index the Database | Database query optimization. Inspect database schema migrations for indexes on foreign keys, frequently filtered columns, unique constraints, and sort criteria. Use query analysis (`EXPLAIN ANALYZE`) to identify sequential table scans on hot query paths. Related: MP-12. |
| WP-04 | Compress images | Asset delivery optimization. Inspect image assets for modern formats (AVIF, WebP), appropriate resolution scaling (prevent serving 4000px images in 200px thumbnails), and automated build/CDN compression pipelines. Related: WL-20, MP-01, MP-15. |
| WP-05 | Loading skeletons | Perceived performance. Inspect asynchronous content loading states for skeleton placeholders or content placeholders that preserve layout dimensions, avoiding Cumulative Layout Shift (CLS). Related: DC-15, WL-12, MP-10. |
| WP-06 | Cache expensive queries | Database and application caching. Inspect in-memory cache implementations (Redis, Memcached, LRU cache) for heavy aggregations, external API results, or computationally intensive database reads. Verify cache invalidation and TTL boundaries. |
| WP-07 | Make sure no N+1 database queries | ORM and query efficiency. Audit ORM relationships and data fetching logic (e.g., in loops or resolvers) to ensure eager loading (`include`, `join`, `select_related`, dataloaders) is used instead of firing individual queries for each related child entity. Related: MP-11. |
| WP-08 | Debounce input handlers | Client-side CPU and network thrift. Inspect search inputs, typeahead selectors, and live filter form controls to ensure handlers are debounced (e.g., 250–400ms) or throttled to prevent firing API requests or DOM updates on every keystroke. Related: MP-05. |
| WP-09 | Split code into chunks | Bundle optimization. Inspect bundler configuration (Vite, Webpack, Next.js, Rollup) for dynamic imports (`import()`), route-based code splitting, and vendor chunk separation to reduce initial JavaScript payload size. |
| WP-10 | add CDN V Server-side caching | Content delivery and edge caching (original text: add CDN V Server-side caching). Inspect deployment configuration for CDN edge caching (Cloudflare, Fastly, CloudFront, Vercel Edge) for static assets and public cacheable routes, alongside application-level caching. |
| WP-11 | Paginate large lists | Unbounded query and render protection. Verify all list endpoints, search results, and database queries enforce maximum limit constraints (cursor or offset pagination) rather than unbounded `SELECT *` without limits. Related: MP-04. |
| WP-12 | Do Lighthouse audit | Automated performance and quality benchmark. Execute Google Lighthouse or Chrome DevTools audit against production builds. Inspect Core Web Vitals: Largest Contentful Paint (LCP), Interaction to Next Paint (INP), and Cumulative Layout Shift (CLS). |
| WP-13 | Compress API payloads | Network transfer efficiency. Verify that web servers and API gateways support Gzip and Brotli compression (`Content-Encoding: br, gzip`) for JSON payloads and text assets exceeding 1 KB. Related: MP-18. |
| WP-14 | Remove Unnecessary re-renders | Frontend UI rendering efficiency. Inspect React/Vue/Svelte component architecture for redundant renders caused by unstable object references, missing memoization of expensive computations, or excessive global state changes. |
| WP-15 | Minify JS and CSS | Asset size minimization. Verify that production build pipelines automatically minify, remove dead code (tree-shake), and strip comments from JavaScript and CSS bundles. |
| WP-16 | Add Lazy Loading | On-demand asset retrieval. Verify that below-the-fold images use native `loading="lazy"`, iframe widgets use deferred loading, and heavy non-critical components are loaded only when scrolled into view. Related: MP-02. |
| WP-17 | Defer non-critical scripts | Critical rendering path optimization. Inspect HTML `<script>` tags for third-party trackers, widgets, and non-essential libraries to ensure they use `defer` or `async` attributes to avoid blocking initial DOM parsing. |
| WP-18 | Remove Unused dependencies | Package and bundle cleanliness. Audit manifests to eliminate dead packages that add unnecessary weight to the node/vendor runtime or client bundle. Cross-reference: AH-01, MP-08. |
| WP-19 | Database connection pooling | Database scalability. Inspect database client configuration (e.g. PgBouncer, Prisma Accelerate, connection pool limits) to ensure serverless or multi-threaded application workers do not exhaust database max_connections under load. |

## Supporting guidance

- Base performance recommendations on actual profiling and traffic expectations. Over-engineering micro-optimizations (like premature Redis caching or complex load balancers) before validating demand introduces needless operational complexity.
